# Flight cancellation rules: public response repair

Checked 16 November 2026 against the [official TripJack Flights API reference](https://tripjack.com/page/api-doc), Fare Rule section, and its linked [Fare Rule.zip samples](https://drive.google.com/file/d/1YJ6uyxJ9cBeJP1MkAkpeO9MJGG4ht75V/view). The reference is JavaScript-rendered; its public script was read to obtain the section and sample-folder links. Only public documentation was read. No authenticated supplier request, booking, payment or cancellation was performed.

The existing review flow already requests `/fms/v2/farerule` using the review booking ID and `flowType: REVIEW`. The defect is downstream: the public projection accepted only `fareRule.miscInfo` as a string. The official examples instead place each route under `fareRule`, followed by `tfr` categories for cancellation, date change, no-show and seat charges. The detailed-rule variant places a string array under the route's `miscInfo`. Those complete policies were being dropped before reaching checkout.

The public boundary now projects only that documented route, category and field structure. The timed samples encode `st` and `et` as numeric strings although the reference table describes numbers; both canonicalize to bounded numbers. Period rules use `pp` instead. The reference explicitly makes time bands and periods mutually exclusive. Unsupported or incomplete categories remain unavailable; unknown nested supplier fields are never recursively exposed. Complete detailed notes are retained within a separate bounded limit, without clipping clauses or interpreting HTML.

Checkout presents the route and cancellation window first, with date changes, no-show, seats and detailed conditions in disclosures. It explicitly identifies routes with unavailable cancellation rules. Amounts are not summed into a refund estimate or assigned a currency/per-passenger basis absent from the response. Structured cancellation fees, taxes, timing and text participate in refresh comparison; ordering changes alone do not trigger a warning.

`tests/flight-fare-rules.test.ts` exercises synthetic examples matching the public sample shapes through the full public review boundary and renderer, repeated projection, unsafe-field stripping, partial/malformed rules, unavailable return-route cancellation, complete detailed notes, meaningful refresh changes and display escaping. Existing legacy note fixtures remain supported.
